# 生成器的真实水平：一个诚实的记录

这个文件记录生成管线三个版本的实测数据。**所有数字都能在仓库里复现**，
这是我们对外讲这个产品时最重要的一张牌：不吹「AI 一键生成」，讲清楚每一版的瓶颈和改进。

## 版本演进与实测结果（本地 qwen2.5:7b，纯 CPU，16GB 笔记本）

| 版本 | 管线 | 实测 | 结论 |
|---|---|---|---|
| v1 | 单次生成整份 JSON + 1 次整体重试 | 4 次生成：类型名重复（"社交条理派"×3）、emoji 拼接（"🤝📝"）、占位符残留（"〈随性派〉"）、轴分布失衡（+0/-7） | **0/4 干净通过**。输出越长，模型犯错机会越多 |
| v2.0 | 三段式（骨架→题目→文案），各段独立门禁重试 | worker2：骨架 2✓ / 题目 3✗ / 文案 1✓；lit-reading：骨架 2✓ / 题目 3✗ / 文案 1✓ | 类型名、emoji、占位符、文案质量**全部解决**（文案段 2/2 一次过）；但**题目段轴平衡 0/2**——7B 靠提示词做不到 ±1 平衡 |
| v2.1 | 题目段改为结构规则：**每题只考 1 条轴（+1/-1/中性各一选项），每轴至少 2 题** | lit-reading 407s 重试后通过；study-style **327s 三段全部一次通过**；travel 409s 重试后通过 | **轴平衡从"求模型"变成"结构保证"**：题目段 3/3 通过（2 次一次过）。v1 的四个内容问题全部消失 |
| v2.2 | 文案阶段注入每个 key 的轴语义；新增 emoji 去重门禁 | 起因：实测发现「极客·科技达人」这个文案配在了"宅+结伴+随性"的 key 上——模型不知道 key 的含义 | 语义错位在机制上堵住；已生成测试经人工润色后全部过新门禁 |

> 为什么要记录失败：面试官问「AI 生成质量怎么样」，拿这页回答，比"挺好的"值钱十倍。

## v2.1 的关键取舍：题目结构的代价

v2.1 强制「每道题只考 1 条轴」，公平性由结构保证，但放弃了「一道题的选项横跨多条轴」的
设计空间。我们对比了人工精写的 `presets/ai-pm.json`——它恰好就是单轴结构，
说明这个取舍与高质量样本的实际做法一致；换来的是**平衡性不再依赖模型的自觉**。

## 人工润色（发布前的人工环节）

生成版定位是「初稿」。`docs/` 里正式发布的 5 个测试中，3 个生成版
（文献阅读人格 / 期末复习风格 / 假期旅行人格）都经过一轮人工润色，典型修改：

- 7B 连续 5 道题的题干一模一样（"复习时你会选择？"）→ 重写题干增加场景变化；
- 一道题的方向打反（"独自复习"被记成社交正向）→ 人工修正；
- 类型名与 key 的轴语义错位（"极客·科技达人"配在宅+结伴上）→ 重写 8 个类型；
- 文案平庸（"木鸡 · 呆板执行"偏贬义）→ 重写为善意、有记忆点的表达。

**改进后这些坑在 v2.2 的门禁与提示词里都被堵住了**，但「发布前人工过一遍」仍是产品规矩。

## 怎么复现

```bash
# 本地 7B 生成（约 5-12 分钟/次）
python generate.py --theme "测测你是哪种打工人" --slug worker --model qwen2.5:7b
# 生成结果与门禁报告在 quizzes/worker.json + quizzes/worker.report.json

# 云端模型（更快更准，需 API key：环境变量 QUIZ_API_KEY 或 .env 的 LIT_API_KEY）
python generate.py --theme "测测你是哪种咖啡" --slug coffee --provider openai --model deepseek-chat

# 网页版：主题 → 三段进度 → 门禁报告 → 下载 HTML
python -m streamlit run app.py
```

- `examples/worker-generator-raw.json`：v1 时代的 7B 原始输出（未润色，附门禁抓到的问题）；
- `examples/worker2-generator-raw.json`：v2.0 的原始输出（类型名/emoji/文案已达标，
  但题目轴平衡未过门禁，副标题还编造了「30 道题」——这个洞已在 v2.0 后用代码兜底堵住）；
- 每次生成的门禁报告（各段尝试次数、每段问题清单、最终分布）都会写在
  `quizzes/<slug>.report.json`，可直接查看。
